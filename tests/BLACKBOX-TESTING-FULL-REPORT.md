## 4. Authentication Flow Analysis

### 4.1 Auth Architecture

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│   Client     │────▶│  Go Backend  │────▶│  Supabase   │
│  (Next.js)   │◀────│  (Gin)       │◀────│  Auth       │
└─────────────┘     └──────────────┘     └─────────────┘
     │                    │                     │
     │  POST /auth/login  │                     │
     │───────────────────▶│                     │
     │                    │  ValidateToken()    │
     │                    │────────────────────▶│
     │                    │                     │
     │                    │  JWT Token          │
     │  {token, user}     │◀────────────────────│
     │◀───────────────────│                     │
     │                    │                     │
     │  Bearer <token>    │                     │
     │───────────────────▶│                     │
     │                    │  Extract user_id    │
     │                    │  Extract user_email │
     │                    │  Extract user_role  │
```

### 4.2 Auth Tiers

| Tier | Description | Example Endpoints |
|------|-------------|-------------------|
| **Public** | No auth required | `/health`, `/auth/login`, `/auth/register` |
| **Optional JWT** | Token parsed if present, not required | `/auth/debug`, `/chat` |
| **Required JWT** | Must have valid JWT | `/auth/profile`, `/silpana/*`, `/aktivitas-siak/*` |
| **Admin-only** | JWT + role='admin' or 'superuser' | `/admin/*`, `/supabase/*`, `DELETE /cache/clear` |

### 4.3 JWT Token Structure

```json
{
  "user_id": "uuid",
  "user_email": "user@example.com",
  "user_role": "admin|user|superuser",
  "exp": 1234567890,
  "iat": 1234567890
}
```

### 4.4 Middleware Auth Chain

1. **OptionalAuth** — Parses JWT if `Authorization: Bearer <token>` present
2. **RequiredAuth** — Blocks with 401 if no valid token
3. **AdminOnly** — Blocks with 403 if role != admin/superuser
