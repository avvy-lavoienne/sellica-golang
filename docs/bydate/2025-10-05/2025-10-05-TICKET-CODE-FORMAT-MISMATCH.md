## Executive Summary

Critical mismatch found between database ticket code generation (`SILP-2025-000001` format) and frontend
validation (`SPL251005D9EC8737` format), causing all ticket lookups to fail with "Format tiket tidak valid"
error even for valid database-generated codes.

## Problem Description

### User Report

User reported that ticket code `SPL251005D9EC8737` (generated by the system) shows error:

```text
Pencarian Gagal
Format tiket tidak valid
```

### Root Cause Analysis

**Database generates**: `SILP-2025-000001` format (old format)
**Frontend expects**: `SPL251005D9EC8737` format (new format)

#### Database Function (Current - WRONG)

Location: `backend/migrations/002_silpana_ticketing_system.sql` (line 117-131)

```sql
CREATE OR REPLACE FUNCTION generate_ticket_code()
RETURNS TEXT AS $$
DECLARE
  year_part TEXT;
  sequence_part TEXT;
BEGIN
  year_part := EXTRACT(YEAR FROM NOW())::TEXT;
  sequence_part := LPAD(nextval('ticket_code_sequence')::TEXT, 6, '0');
  RETURN 'SILP-' || year_part || '-' || sequence_part;
END;
$$ LANGUAGE plpgsql;
```

**Output**: `SILP-2025-000001`, `SILP-2025-000002`, etc.

#### Frontend Validation (Current - CORRECT)

Location: `frontend/src/lib/ticketing/utils.ts` (line 216-220)

```typescript
export function isValidTicketCode(code: string): boolean {
  // Format: SPL + YYMMDD + 8-character hex
  const pattern = /^SPL\d{6}[0-9A-F]{8}$/i;
  return pattern.test(code.trim());
}
```

**Expected**: `SPL251005D9EC8737` (SPL + 251005 + D9EC8737)

#### Format Comparison

| Component | Database Format | Frontend Format | Match |
|-----------|----------------|-----------------|-------|
| Prefix | `SILP-` | `SPL` | ❌ Different |
| Date | `2025-` (full year with dash) | `251005` (YYMMDD) | ❌ Different |
| Identifier | `000001` (sequential) | `D9EC8737` (8-char hex) | ❌ Different |
| Separators | Uses dashes (`-`) | No separators | ❌ Different |

**Example codes**:

- Database: `SILP-2025-000001`
- Frontend: `SPL251005D9EC8737`

### Impact

**CRITICAL**: 100% of ticket lookups fail because:

1. User submits form → Database generates `SILP-2025-000001`
2. User tries to lookup with `SILP-2025-000001` → Frontend validation rejects it
3. Error message: "Format tiket tidak valid"
4. **Result**: Ticket lookup feature is completely broken

```sql
RETURNS TEXT AS $$
DECLARE
  date_part TEXT;
  hex_part TEXT;
  new_code TEXT;
  code_exists BOOLEAN;
  attempt_count INTEGER := 0;
  max_attempts INTEGER := 100;
BEGIN
  -- Get current date in YYMMDD format
  date_part := TO_CHAR(NOW(), 'YYMMDD');
  
  -- Generate unique code
  LOOP
    -- Generate 8-character hex string
    hex_part := UPPER(SUBSTRING(MD5(RANDOM()::TEXT || NOW()::TEXT || attempt_count::TEXT) FROM 1 FOR 8));
    
    -- Combine parts: SPL + YYMMDD + 8-char hex
    new_code := 'SPL' || date_part || hex_part;
    
    -- Check if code already exists
    SELECT EXISTS(SELECT 1 FROM silpana WHERE ticket_code = new_code) INTO code_exists;
    
    IF NOT code_exists THEN
      RETURN new_code;
    END IF;
    
    attempt_count := attempt_count + 1;
    IF attempt_count >= max_attempts THEN
      RAISE EXCEPTION 'Unable to generate unique ticket code after % attempts', max_attempts;
    END IF;
  END LOOP;
END;
$$ LANGUAGE plpgsql;
```

**Output**: `SPL251005D9EC8737` (matches frontend validation!)

### Why Script Was Never Applied

The script `update-ticket-code-format.sql` is located in `frontend/scripts/` directory, suggesting it was
created but never executed on the database. The migration files in `backend/migrations/` still use the old
format.

## Solution

### Option 1: Update Database Function (RECOMMENDED)

Update the database function to match frontend validation.

#### Step 1: Create New Migration

File: `backend/migrations/007_update_ticket_code_format.sql`

```sql
-- ============================================================================
-- Update Ticket Code Format to SPL + YYMMDD + 8-char hex
-- Version: 1.0
-- Date: 2025-10-05
-- Description: Fix ticket code format mismatch
-- ============================================================================

-- Drop old sequence (no longer needed)
DROP SEQUENCE IF EXISTS ticket_code_sequence;

-- Drop old function
DROP FUNCTION IF EXISTS generate_ticket_code() CASCADE;

-- Create new function with SPL + YYMMDD + 8-char hex format
CREATE OR REPLACE FUNCTION generate_ticket_code()
RETURNS TEXT AS $$
DECLARE
  date_part TEXT;
  hex_part TEXT;
  new_code TEXT;
  code_exists BOOLEAN;
  attempt_count INTEGER := 0;
  max_attempts INTEGER := 100;
BEGIN
  -- Get current date in YYMMDD format
  date_part := TO_CHAR(NOW(), 'YYMMDD');
  
  -- Generate unique code
  LOOP
    -- Generate 8-character hex string
    hex_part := UPPER(SUBSTRING(MD5(RANDOM()::TEXT || NOW()::TEXT || attempt_count::TEXT) FROM 1 FOR 8));
    
    -- Combine parts: SPL + YYMMDD + 8-char hex
    new_code := 'SPL' || date_part || hex_part;
    
    -- Check if code already exists
    SELECT EXISTS(SELECT 1 FROM silpana WHERE ticket_code = new_code) INTO code_exists;
    
    -- If code is unique, return it
    IF NOT code_exists THEN
      RETURN new_code;
    END IF;
    
    -- Increment attempt counter and check limit
    attempt_count := attempt_count + 1;
    IF attempt_count >= max_attempts THEN
      RAISE EXCEPTION 'Unable to generate unique ticket code after % attempts', max_attempts;
    END IF;
  END LOOP;
END;
$$ LANGUAGE plpgsql;

-- Make function SECURITY DEFINER
ALTER FUNCTION generate_ticket_code() SECURITY DEFINER;

-- Grant execute permissions
GRANT EXECUTE ON FUNCTION generate_ticket_code() TO anon;
GRANT EXECUTE ON FUNCTION generate_ticket_code() TO authenticated;
GRANT EXECUTE ON FUNCTION generate_ticket_code() TO PUBLIC;

-- Update set_ticket_code function (if exists)
CREATE OR REPLACE FUNCTION set_ticket_code()
RETURNS TRIGGER AS $$
BEGIN
  -- Generate ticket code if not provided
  IF NEW.ticket_code IS NULL OR NEW.ticket_code = '' THEN
    NEW.ticket_code := generate_ticket_code();
  END IF;
  
  -- Update last_updated timestamp
  NEW.last_updated := NOW();
  
  -- If this is an update and status changed, log to history
  IF TG_OP = 'UPDATE' AND OLD.ticket_status IS DISTINCT FROM NEW.ticket_status THEN
    INSERT INTO ticket_history (ticket_id, status_from, status_to, changed_by, notes)
    VALUES (NEW.id, OLD.ticket_status, NEW.ticket_status, 'system', 'Status changed via trigger');
  END IF;
  
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Make trigger function SECURITY DEFINER
ALTER FUNCTION set_ticket_code() SECURITY DEFINER;

-- Grant execute permissions
GRANT EXECUTE ON FUNCTION set_ticket_code() TO anon;
GRANT EXECUTE ON FUNCTION set_ticket_code() TO authenticated;
GRANT EXECUTE ON FUNCTION set_ticket_code() TO PUBLIC;

-- Recreate trigger
DROP TRIGGER IF EXISTS trigger_set_ticket_code ON silpana;
CREATE TRIGGER trigger_set_ticket_code
  BEFORE INSERT OR UPDATE ON silpana
  FOR EACH ROW
  EXECUTE FUNCTION set_ticket_code();

-- Add comments

COMMENT ON FUNCTION set_ticket_code() IS 'Trigger function to auto-generate ticket codes and log history';
```
